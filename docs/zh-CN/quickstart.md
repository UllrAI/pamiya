# Pamiya 上手指南

[English](../en/quickstart.md) · [交给 DSH 安装](install-with-dsh.md) · [完整使用说明](dsh-plugin.md)

Pamiya 让 DSH 使用你的多台电脑执行工作。对话、模型和账号继续使用 DSH；安装后，本机就是第一个 Worker。

## 准备

先安装并打开 [DeepSeek Harness](https://www.deepseek.com/harness/)。已验证桌面版 `0.2.0-rc.2` 和 Web Host `0.2.1-alpha.4`。**桌面界面安装不需要 Git、源码或额外安装 Node.js。** 仅其他电脑上的独立 Worker 需要 Node.js 22.19 或更新版本。

当前发布为 `v0.3.0` 预览版，安装包在 [GitHub Releases](https://github.com/UllrAI/pamiya/releases/tag/v0.3.0)。尚未发布到 npm，请使用下面的完整安装地址。

## 1. 安装插件

1. 在 DSH 左侧点击 **插件 → 添加插件**。部分版本显示为 **安装第三方插件**。
2. 把下面整条地址粘贴到包名/安装地址输入框，点击 **安装**：

```text
https://github.com/UllrAI/pamiya/releases/download/v0.3.0/pamiya-dsh-plugin-0.3.0.tgz
```

3. 完成后选择 **立即启用**。如果提示需要重启，完全退出 DSH 后重新打开；只关闭窗口不一定会退出应用。
4. 左侧出现 **Pamiya**，说明界面已经加载。

如果你更希望让 Agent 完成安装，直接使用[这份安装任务文档](install-with-dsh.md)。

## 2. 使用本机节点

1. 打开 **Pamiya → 计算节点**，本机自动显示为“这台电脑”。不需要先配置 MQTT 或再次添加本机。
2. 等待 **可用** 后点击 **检查连接**，在 **运行记录** 查看真实结果。
3. 节点详情的 **Agent 能力** 显示 DSH、Codex、Claude Code、Pi；缺少时点击安装，随后进行合成验证。

本机通过 DSH 托管的本地通道工作。默认复用 DSH 模型与鉴权，可选 Agent 自己的独立配置，详见[Agent 与自定义动作](agent-workers.md)。

## 3. 让 Agent 做第一次工作

在 DSH 对话中发送：

> 用 Pamiya 查看可用节点，在这台电脑上检查连接，然后统计文本 Hello Pamiya。请告诉我实际执行结果。

预期能看到本机操作系统、Node.js 版本，以及 **12 字符、1 行、2 词**。第一次对话还需要 DSH 已经登录模型账号或配置好模型；Pamiya 不另设模型账号。

## 在对话里选择哪台电脑执行

输入框底部工具栏的 **执行节点** 会列出本机和已接入的电脑，无需记住节点 ID。

- **自动选择**：可以说“用 Pamiya 在 Linux 测试节点检查系统”。未指定时优先本机，再选择可用且支持该能力的节点。
- **固定某个节点**：选中“Linux 测试节点”，再说“检查所选电脑的系统信息”。选择保存在当前对话，切换对话分别记忆；要同时比较多台电脑，先切回“自动”。
- **管理节点**：直接打开配置页，可添加、重命名、暂停节点或调整本机能力。

切换只影响后续任务。所选节点离线、正忙或缺少能力时会明确提示，不自动换电脑。已移除的选择也会保留提示，直到你重新选择。

**选择器只控制 Pamiya 工具的执行位置。** DSH 自带的 bash、文件和浏览器工具仍在 DSH 本机运行，Agent 本身也没有迁到远端。公共测试连接仅支持演示与系统检查，选中 Linux 不等于可以执行 `ping` 等 Shell 命令；需要先使用私有 MQTT 连接，并在对应 Worker 启用命令能力。

![对话中选择 Linux 节点并获得真实结果](../../packages/dsh-plugin/design/worker-picker.zh-CN.png)

## 4. 可选：再接入一台电脑

1. 先到 **连接设置 → RunMQTT 公共测试连接 → 填入当前测试参数 → 保存并连接**。随后选择 **添加节点 → 另一台电脑或服务器**，填写名称，创建配对。
2. 在另一台电脑安装 [Node.js 22.19 或更新版本](https://nodejs.org/en/download)，并把界面下载的 Worker 放进那台电脑的“下载”文件夹。
3. 在 Pamiya 选择对应系统，复制启动命令，在**另一台电脑**的终端运行。剪贴板不可用时，点击 **显示命令以手动复制**。
4. 回到 DSH，等第二个节点显示 **可用**，再点击 **体验多节点**。

公共连接只用于固定合成 Agent 任务、回声、等待、文本统计及系统检查。远端真实工作使用自己的私有连接；本机能力不受公共 MQTT 设置影响。

本机不用重复安装 Worker。配对码仅交给自己的那台电脑，每台分别配对；不要把它放到公开文档里。终端关闭或电脑休眠后，远端可能离线；服务器长期运行可按[运行说明](dsh-plugin.md)交给进程管理器托管。

## 常见问题

| 情况 | 处理 |
|---|---|
| 没有 Pamiya 入口 | 检查插件是否已启用，再完全退出并重新打开 DSH。 |
| 安装地址下载失败 | 在 Releases 页面下载 `.tgz`，在同一安装框填入它的本机绝对路径。切换 npm 镜像不能解决 GitHub 本身连不上的问题。 |
| 提示 DSH 版本不兼容 | 查看安装包支持版本，使用匹配版本；本指南不要求写入兼容性豁免。 |
| 公共连接失败 | 重新“填入当前测试参数”，再保存连接；账号可能轮换，服务也可能临时不可用。 |
| 本机节点已停止 | 打开节点详情，点击“启动本机节点”；主动停止后不会自动重启。 |
| 其他电脑一直等待连接 | 确认命令在对应电脑运行、Node.js 版本满足要求、配对未过期；过期后在详情重新配对。 |
| 对话没有模型可用 | 先完成 DSH 的模型登录或配置，节点界面体验不依赖模型。 |

桌面完整验收使用 macOS，远端使用 Linux；Windows 的实机进程行为尚未验收，详见[验证记录](dsh-verification.md)。

## 更新与停用

新版本会提供新的发布地址。更新时沿用 DSH 插件管理器；界面要求先卸载时，移除插件包后再安装新地址，不删除 DSH 的数据目录。停用可在 **插件** 中关闭 Pamiya；本机托管 Worker 随插件停止。远程 Worker 需要在对应电脑停止。

开发者的源码安装和 CLI 安装见[完整说明](dsh-plugin.md)。Web profile 可使用 `dsh plugin --profile web add <上面的安装地址>`，然后启用插件。

## 让能力跟着任务走

打开节点卡片的 **Skills**，选择 **运行合成示例**。首次缺依赖时，点击 **准备并继续**，即可看到 Agent 读取资源、运行脚本并回传结果。自己的 Skills 可通过本机文件夹添加；真实远端同步由部署者配置一次 HTTPS 文件中转，不要求节点与本机互通。[完整指南](skills.md)。
