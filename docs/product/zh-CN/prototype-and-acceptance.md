## 当前交付范围

原型位于 `prototype/`，使用 React/Vite、Phosphor 图标和 Markdown 预览。所选视觉保存在 `prototype/design/selected-home.png`。通过同一个页面的状态切换完成主要流程，未引入路由框架、服务端应用或通用工作流引擎。

| 已实现的交互 | 明确的模拟/限制 |
|---|---|
| 首页、侧栏、对话、执行中补充 | 不调用真实模型；任意目标使用固定的示例文档与修订段落 |
| 活动展开、澄清、连接阻塞、读取失败重试 | 活动与失败由预设场景确定，不代表真实工具结果 |
| 停止请求、停止确认、提交回执核对 | 提交通知只模拟，无真实消息发送 |
| 成果预览、文本编辑、下载、版本历史 | 无云存储、协同编辑、跨标签合并 |
| 搜索、重命名、归档/撤销 | 使用浏览器本地保存，无账号/跨设备同步 |
| 文本附件、拖放、引用历史 | 单文件 5 MB；文本 20,000 字符上限；二进制只保留信息 |
| 每日/每周安排、时区、启停、手动触发、执行入口 | 只支持 Asia/Shanghai 与 UTC；没有后台调度 |
| 显式记忆增改删、来源、撤销；演示数据导出 | 不自动提取记忆，不用它声称真实模型已记住 |

后续真实能力接入不改首页心智：模型/工具放在服务端适配层，资源通过工具与连接接入，运行时状态映射为当前活动与成果。

## 建议体验顺序

1. 首页输入目标，查看执行中活动；在执行中补充一个要求，观察它成为同一轮上下文。
2. 完成后打开成果，编辑并保存；切换历史版本，下载，再回到对话继续完善。
3. 点击“原型预览”或“更多 → 体验演示”，依次体验澄清、缺连接、失败恢复与未知提交。
4. 新一轮执行中点击停止，观察“正在停止”到“已停止”；不会迟到生成成果。
5. “更多 → 持续安排”填写名称、目标、频率和时区，核对下一次时间；模拟触发后进入执行记录，再暂停安排。
6. 添加一条记忆，编辑、删除、撤销；搜索对话、归档、找回；刷新后已保存内容仍在。

原型刷新会中断本地模拟，提供继续入口。真实产品刷新只重连权威运行状态，不能复用这个本地模拟行为作为云端运行契约。

## 验收矩阵

| ID | 场景 | 必须看到的结果 |
|---|---|---|
| A01 / R01–R03 | 无工具配置发出目标 | 即刻开始；同一目标一个 Run；空白禁用 |
| A02 / R02 | 输入法、附件、引用 | 无误发送；附件可移除；未解析内容不被称为已读 |
| A03 / R05 | 运行中补充 | 同一 Run 记录补充，不重复提交动作 |
| A04 / R04 | 受众缺失 | 一个具体问题，快捷/自由回答后继续 |
| A05 / R09 | 缺少工作区 | 说明用途与范围；连接后原流程继续 |
| A06 / R10 | 读取失败 | 保留进度，同一逻辑意图增加尝试后完成 |
| A07 / R06 | 提交停止请求 | 先正在停止，再确认已停止；不再派生新操作 |
| A08 / R06、R10 | 已提交且回执未知 | 只有核对入口，无盲重试；其他对话可继续 |
| A09 / R07 | 编辑成果与后续修改 | 新版本生成，原版本保留，人工内容不消失 |
| A10 / R07 | 关闭未保存编辑 | 保存/放弃/继续编辑；查看历史不改当前版本 |
| A11 / R08 | 搜索、名称、归档 | 查询命中、可恢复、重要待核对工作不被隐藏 |
| A12 / R12 | 刷新与存储失败 | 保存内容可读；模拟执行明确中断；失败提示未保存 |
| A13 / R13 | 每日/每周与时区 | 下一次是未来的正确时刻；暂停不停止当前 Run |
| A14 / R14 | 记忆管理 | 来源可见、编辑删除可撤销、不扩大权限 |
| A15 / R17 | 键盘、390 px、平板 | 无关键控件遮挡或横向溢出，弹窗焦点与关闭可用 |
| A16 / R11、R15–R16 | 真实身份、设备、事件 | 生产集成验收项；不以当前原型宣称通过 |

可执行模型测试覆盖停止、未知结果、读取重试、补充输入、刷新、版本与时区边界；浏览器检查覆盖主流程和界面状态。[QA 报告](../../../prototype/design-qa.md)记录本轮实际检查，表中其他生产验收不因此自动通过。

## 生产接入顺序

1. 接入身份与会话服务、模型、一个云端执行器、文件对象存储；保持 Session 串行、工具意图稳定 ID 与持久化结果。
2. 用真实服务事件替换本地 tick 模拟；实现幂等消息提交、断线游标同步、取消确认、重要效果查询、成果版本条件写入。
3. 接入一个真正需要的连接器，验证范围不足、撤销、能力未就绪和环境失效；随后接入定时服务与最小记忆存储。
4. 按用户目标引入桌面/Edge/设备、专家 Agent、事件规则，分别验证环境归属、远程 ID 跟踪与停止能力。

每一步都能交付一条完整体验，不让尚未启用的增强机制进入首版门槛。生产故障验收仍遵循[可靠执行文档](../../zh-CN/reliability.md)。
