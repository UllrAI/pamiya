# 交互规格

[索引](README.md) · [English](../en/interactions.md) · [验收矩阵](prototype-and-acceptance.md)

## 1. 首次使用与发起目标

进入后只见 Pamiya、历史侧栏和“有什么想交给我？”输入区。可以立即写目标，不以欢迎向导、工作区创建或工具配置拦住。生产环境需要登录时仅处理身份；部署者应已准备好默认模型与云端执行能力。

已有需处理事项或未读结果时显示“待处理”入口，规则见第 10 节；首次使用不展示空任务面板。用户无需先创建项目或选择工作类型。Pamiya 从目标形成简短交付预期，例如“整理一份含来源的报告”，信息足够就开始。[生命周期与归属](information-architecture.md#一件事的生命周期)由原对话、Run 与成果关联承载。

输入框支持多行、附件、拖放与 `@` 引用对话/文件。Enter 发送，Shift+Enter 换行，中文输入法选词的 Enter 不发送。空白禁用发送；仅附件时可用默认“根据这些文件整理方案”，允许随后补充目标。草稿按对话保留；切换回来不丢失。

生产附件区分读取/上传中、可用、失败和不支持；准备未完成的资料不作为已读上下文。文件过大给出可行的替代。当前原型限制单文件 5 MB，文本最多读取 20,000 字符；PDF、图片等只保存信息并明确提示未解析，不上传外部服务。

发出后进入对话。用户消息先出现，Agent 给出简短行动说明，随即开始。要求已经足够时不问“是否开始”。标题自动形成，可在对话设置中修改。网络提交失败保留草稿，生产客户端用稳定请求 ID 防止重复创建。

## 2. 理解、执行与补充方向

活动摘要说明正在做什么，如“正在阅读资料”“正在完善方案”；可展开已经发生的工具活动及来源。不能展示伪造百分比、固定三阶段进度或私有推理全文。普通读取失败由运行时自动恢复；不把每次工具调用变成弹窗。

执行中新消息按意图处理，不把所有消息都当成补充，也不要求先选择“提问/指令”模式。可以合入当前交付的要求按补充处理；明确放弃当前目标才按替换处理。当前阻塞问题的答案优先用于解除对应阻塞。

| 新消息 | 默认处理 | 面向用户的反馈示例 |
|---|---|---|
| “报告再短一点” | 同一 Run 接受约束，在下一可用边界应用 | “已记下缩短篇幅，接下来的修改会按这个要求处理。” |
| “这个数字依据是什么？” | 回答问题，当前目标继续；必要读取复用当前协调与资源边界，不另开冲突执行 | “这个数字来自……。报告仍在继续整理。” |
| “不要报告了，改成演示提纲” | 明确替换：停止旧目标的新操作，跟踪在途结果；可安全开始后以本消息创建新目标与 Run，并关联旧记录 | “正在停止报告整理，之后改做演示提纲；已经生成的内容会保留。” |
| “完成后再整理附件” | 保存为可查看的后续请求，当前目标不变；开始时才创建新目标的 Run | “已排在报告之后，可以在这里撤回。” |

一个不同目标未说明时机时，默认排在当前工作后并明确告知，不暗中替换。只在目标/对象或先后关系不明且会明显改变结果时问一个具体问题；明确的修改、替换与停止不重复审批。无法立即回答、应用或停止时说明等待原因，不能用“收到”暗示已经生效。

同一消息可以同时补充要求、提问和安排后续，分别处理并合并反馈；这些不是用户必须掌握的互斥消息类型。只澄清其中不明的部分，不阻止其他已明确的工作。

接收与应用分别说明：保存新消息及其处理去向后才确认接收，实际采用后更新活动；若原轮已经结束，说明补充未影响已交付版本，并按明确的修改要求关联新 Run 修订。停止/替换期间的含糊补充先澄清，不恢复旧目标。重连或重复送达按同一消息及处理记录恢复，不重复排队、创建或切换目标。

后续请求仅在有关联时显示于当前活动下，可查看原文和撤回；不建设通用队列管理页。成功完成当前目标后按接收顺序执行，执行时使用最新有效授权；当前工作停止、最终未完成或有重要效果待核对时，暂存尚未开始的请求，并提供继续后续/撤回入口，避免刚停止就自动重启。撤回只取消尚未开始的请求；若已开始，明确显示并使用正常停止语义。已接受的后续请求及暂存状态跨刷新保留。

替换目标时，排在旧目标之后的请求仍暂存，不默认为新目标的后续。继续后续不绕过前一轮的停止确认或必要核对；等待原因应明确，其他对话的独立工作仍可继续。

点击历史可以离开，真实云端执行继续；需要用户的事项与未读结果汇入待处理并链接原对话。默认只在应用内展示结果，不擅自开系统通知、邮件或消息推送。尚未看见的结果不标成已读。

当前原型用有限中文规则演示上述处置，不进行真实语义判断。可用“报告再短一点；这个数字依据是什么？完成后再整理附件”演示混合意图，“不要报告了，改成演示提纲”演示替换；不明确的输入提供就地澄清，不要求所有消息先选模式。问答返回明确标注的演示说明，成果内容仍为固定示例与修订段落。

## 3. 只澄清必要信息

受众、目标或关键输入不同会明显改变成果时，问一个具体问题。例如“这份介绍主要给谁看？”同时提供“新用户 / 团队成员 / 投资人”快捷答案和自由输入。收到答案继续同一轮，不重新创建工具意图。

不必把“缺少截止时间”“没有偏好字体”都变成阻塞。可以合理默认、注明假设并开始。暂时不回答可切换对话；结束本轮后保留上下文。

## 4. 按需连接与授权

缺少资源时，直接在对话说明对象与用途：“需要读取演示工作区的资料。”操作提供连接、换资料或结束本轮。连接弹窗显示资源、可访问范围与真实状态；明确点击连接本身就是该范围内的授权，不再加一次通用确认。

生产连接经过相应 OAuth/本地代理流程，凭据不进入消息正文与模型上下文。连接完成后回到同一对话、继续原 Run；失败保留目标与已完成内容。撤销后不再安排依赖该资源的新操作，跟踪在途操作，其他资源与对话不冻结。

选择“换资料”时可添加文件或消息、移除该目标对原资源的依赖；资料足够则继续同一 Run，否则只说明仍缺的内容。不能一边接受替代资料，一边继续无条件要求原连接。结束本轮才终结这次推进，连接问题本身不另建一件事。

桌面/Edge/设备入口在具体目标需要时出现。选择的是工作现场或物理设备，Worker 是实现归属。提示“已连接，摄像头不可用”比单一绿色在线状态更准确。专家 Agent 委托显示目标、进展、成果和实际可用的停止操作；远程超时按任务 ID 查询，不创建第二个专家任务。

## 5. 完成与成果迭代

完成消息给出结论、成果入口和必要限制，避免“工具调用成功”式汇报。点击成果在右侧展开文档；窄屏切到成果全屏。保留对话上下文和输入位置。成果区提供标题、当前版本、编辑、下载与关闭；操作不会把用户带离对话。

编辑进入 Markdown 文本，保存创建新版本，历史版本可查看与下载。取消、切换对话或关闭时有未保存内容，才询问保存/放弃/继续编辑。内容未变不提醒。查看历史不替换当前版本，编辑按钮禁用，并标明正在查看历史。

回到对话要求修改时，更新同一成果的下一版本并保留人工内容。生产环境按版本比较后修改，不能让迟到的执行结果覆盖用户修改。当前原型用追加修订段落模拟语义修改，不声称具有真实编辑智能。

没有文件类成果时，可交付有证据的可读回复；不为每个简短问题强制创建文档。文件类型预览能力不足时仍应给出类型、大小和下载入口，不能空白冒充预览。

结束时简明列出实际交付、未完成部分与原因；仍需核对的效果保持可见。可恢复读取故障留在恢复流程，决定不再继续后才给出最终未完成结论。完成后的纯询问只回答；“继续修改这份报告”等明确要求在原对话关联新 Run、更新同一成果，不复活旧执行或另复制一份报告。目标、既有成果和版本在跨天返回后仍可找回。

## 6. 停止、失败与未知结果

| 状态 | 文案与动作 | 语义 |
|---|---|---|
| 正在推进 | 停止执行；可补充方向 | 继续当前目标 |
| 正在停止 | “已停止安排新操作，正在等待当前操作退出” | 停止请求已记录；不宣称执行已结束 |
| 已停止 | 保留已有内容，可发送新消息；未决效果仍单独可见 | 已确认停止；无法确认的远端执行仍显示正在停止/待核对 |
| 读取失败 | 说明保留进度；重试读取/结束本轮 | 仅安全读取重试，同一意图增加尝试 |
| 提交结果待核对 | 核对回执；其他对话继续 | 已提交的重要效果不能盲目重复 |
| 需要连接 | 连接、替换资料或结束 | 只阻塞依赖的资源 |
| 需要信息 | 快捷答案或自由输入 | 保存上下文，释放计算 |
| 恢复中/中断 | 拉取权威状态；必要时显式继续 | 不把丢线误报失败，也不虚构后台执行 |

对外发布、提交订单、发送消息等效果发生后，停止无法撤回已完成动作。先查询业务结果；有证据后再显示已完成、未发生或仍未知。无法核对时说明需要人工处理的具体对象，不全局冻结工作。原型提供“演示通知已提交，回执未知”的场景，核对只更新结果，不重复提交。

父 Run 停止时停止派生新任务并跟踪子任务。第三方不支持停止时显示真实限制及后续跟踪；不能用统一“已停止”掩盖远程仍运行。可恢复运行的“继续”与定时安排的“恢复安排”含义分别说明，不承诺任意工具/远程 Agent 的暂停恢复。

“停止执行”默认停止当前 Run，并暂存当前对话尚未开始的后续请求，反馈暂存数量；不会撤销已经完成的效果，也不暂停未来安排。用户明确要求撤回后续请求或暂停相关安排时一并执行并分别反馈。没有相关安排时不添加额外确认或管理步骤。

## 7. 历史与上下文复用

历史按最近使用排序，搜索覆盖标题与消息，支持重命名与归档。归档是可恢复整理，成功后提供撤销，搜索可包含已归档内容。归档不停止执行、撤回后续请求、暂停安排或标记结果已读；相关工作仍在继续时用一条简短反馈说明，不要求先逐项结束。未决事项与未读结果仍留在待处理，可直接打开已归档对话；打开本身不自动恢复归档标记。

引用历史通过 `@` 选择明确对话，输入区显示可移除的资料标签；生产应包含所选版本与范围。用户引用一份对话不等于授权扫描所有历史。长标题省略，查看/编辑时可读完整内容。

“继续上次那份报告”能明确定位时回到原对话和成果；指向不清时只让用户选择相关来源。新对话中的历史引用先作为资料，不复制仍在执行的工作。用户明确另做一个目标时再按新目标开始，并保留来源关联。

## 8. 持续安排与事件触发

从相关对话或更多菜单创建。只填名称、目标、每日/每周、时间、时区；先显示下一次具体发生时间再保存。选择 Asia/Shanghai 与 UTC 是当前原型范围，生产用 IANA 时区处理夏令时，重复/缺失时刻的策略必须明确。

首版错过触发采用跳过，不默认积压补跑。一个安排的上次执行仍在进行时，本次触发记为合并，不额外启动冲突执行。暂停只禁用未来触发，当前执行继续；停止当前执行到对应对话操作。恢复后从下一个未来时刻开始。

每次实际触发保留发生来源、对话/Run 与结果入口；需要用户动作或有新结果时沿用第 10 节，不要求逐个检查安排列表。暂停安排不清除此前未处理事项或未读结果。暂停/移除安排影响未来触发，与某次执行结束分别报告。

列表显示启停、下一次时间、最近执行入口。原型“模拟触发”创建一次演示对话；不会注册后台任务、发送通知或在页面关闭后运行。用户移除安排可撤销。

事件型规则属于随后接入：选可信来源（例如指定目录新增文件），限定简单条件与目标，显示合并/冷却策略、启停和最近执行。规则版本与事件去重在服务端保存。用户不用配置事件总线、编排图或给每条遥测调用模型。

## 9. 记忆、设置与数据

记忆管理显示内容与来源，支持主动添加、编辑、删除，删除后短时可撤销。先不做自动吸收、向量库面板或记忆分层设置。偏好只影响表达与上下文选择，不改变连接权限。

设置保留少量实际需要的选项与演示数据导出，不放租约、重试轮次、Topic、模型温度等内部参数。生产另需账号、连接撤销和数据管理，但不得把它们填到首页当作“功能齐全”。

原型保存于当前浏览器；存储失败时明确提示未保存，并允许下载成果或导出数据。刷新保留已保存消息与版本；本地模拟执行标记中断，已提交的未知效果仍进入核对。跨浏览器/多标签冲突、云同步和灾难恢复不由原型提供。

## 10. 返回后的待处理入口

有内容时，侧栏在历史前显示“待处理”和按件合并的数量；侧栏收起及手机时保留可见入口。点击打开轻量列表，分为“需要你处理”和“有新结果”。新对话输入与草稿不被替换，没有内容时不摆放空状态任务面板。

“需要你处理”只包含实际需要用户的信息、连接、失败选择、人工核对或暂存后续请求；普通运行和自动恢复不加入。“有新结果”包含尚未查看的交付、修订以及最终未完成/停止结论。分组、顺序和去重遵循[待处理读模型](information-architecture.md#返回后的待处理读模型)，不把每个 Task、每条消息或每版成果都做成待办。

条目用“报告缺少第二份资料”“报告有新版本”等具体文案，附一个主要动作。点击定位原对话中的相关问题/结果，必要时打开对应成果；提供足够上下文，用户可直接补充、连接、换资料、继续后续或结束，不另填一份处理表。

打开列表不清除数量；在原对话实际看到对应结果才标记已读。处理项只有真实补齐、解决、结束普通等待或撤回请求后才移出第一组；看到错误不会将其当作解决。未知重要效果须经核对，不能用结束/归档清除。新版本或新问题可以再次进入，重复回报不会重复提醒；旧结果的已读回报不清除后来新增的结果。已读位置和处理事实持久化；暂时无法同步时显示同步问题并允许重试，不伪装为已处理完毕。

当前原型按目标来源汇总待处理，并把具体结果的已读标记、消息处置与暂存请求保存在当前浏览器。只有可见对话结果或对应成果版本才触发已读；打开列表不清除处理项。旧版浏览器数据会迁移保留。真实服务权威状态、同步失败与跨客户端一致性仍是生产接入要求。
