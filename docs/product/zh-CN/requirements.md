# 需求与范围

[索引](README.md) · [English](../en/requirements.md) · [交互规格](interactions.md)

## 定位与用户

Pamiya 是长期个人 Agent。用户不必理解 Harness、Worker、Task 或 MQTT，就能给出目标、提供资料、看到有意义的进展、纠正方向并拿到成果。一次对话可以持续多轮，Agent 的长期身份与用户明确保存的偏好可以跨对话存在。

首要用户是希望把研究、整理、写作和日常工作交给 Agent 的个人。开发者和设备使用者可扩展执行范围，但云端任务必须独立成立。工作目录、浏览器和设备都是完成目标的资源，不决定产品首页的组织方式。

| 场景 | 用户想完成的事 | 成功证据 |
|---|---|---|
| 理解与决策 | 阅读多份资料，比较方案 | 有来源、说明不确定性的可读结论 |
| 创建与修改 | 从目标产出方案、文档或代码 | 成果可打开、修改、下载并继续迭代 |
| 跨资源执行 | 使用已连接工作区或特定环境 | 使用正确资源，结果对应实际目标 |
| 持续承担 | 定期整理资料或响应明确事件 | 看清触发条件、下一次时间、每次结果，可暂停 |
| 回到之前 | 接续上次讨论及成果 | 上下文与版本仍在，不必重新解释 |

不假定用户都需要项目、编程、设备或自动化。首次使用不用选择 Agent 类型、设计流程图或安装 Worker。

## 产品原则

1. 直接开始。一个默认 Personal Agent 接收自然语言和资料。部署者预先配置模型与默认云端能力；终端用户不承担运行时初始化。
2. 自主推进。在已有授权范围内理解目标、规划与使用工具，避免每步确认。可逆、低影响工作允许合理默认并说明假设。
3. 适时可见。展示当前活动、关键结果和阻塞原因，详情可展开。无需暴露私有推理过程，也不用固定步骤条暗示每个目标都有三步。
4. 保持连续。对话、当前推进、成果与长期记忆分别保存；计算可释放，用户的工作不消失。
5. 以目标验收。工具返回成功不等于目标完成；需要有可读结论或成果引用，并核对仍可能产生重要效果的在途工作。
6. 边界具体。需要用户时说明缺什么、用于哪一步、有什么选择；不显示笼统风险评分或重复审批。

## 功能需求与优先级

P0 是首版闭环必需，P1 是紧随其后的可交付扩展，P2 需要明确业务触发。

| ID | 级别 | 需求与验收条件 |
|---|---|---|
| R01 | P0 | 打开首页即可输入目标；没有工具时仍能完成默认云端工作；空白不能发送 |
| R02 | P0 | 多轮对话、附件与所选历史上下文；发送后不重复创建同一次推进；中文输入法回车不误提交 |
| R03 | P0 | Agent 自主调用可用工具；活动摘要简明，详情按需查看；等待时不持续占用模型循环 |
| R04 | P0 | 只澄清改变结果的重要缺口；可提供快捷答案，也允许自由输入 |
| R05 | P0 | 执行中可补充方向；在安全边界吸收补充；互斥目标需明确取消或排队 |
| R06 | P0 | 停止区分请求中与已确认；保留已交付成果；重要已提交动作先查询，避免重复执行 |
| R07 | P0 | 成果预览、编辑、下载、版本查看与对话迭代；人工编辑不会被静默覆盖 |
| R08 | P0 | 历史、搜索、重命名、可恢复归档；离开当前对话不会让真实云端执行停止 |
| R09 | P0 | 需要新资源时在原流程连接；说明对象与范围；失败只阻塞相关工作 |
| R10 | P0 | 失败说明已完成内容、原因和可做的下一步；安全读取可重试，未知重要效果不可盲重放 |
| R11 | P0 | 默认单个用户身份隔离数据和资源；已有授权有效，不为每个普通操作弹审批 |
| R12 | P0 | 页面恢复后重建权威执行状态；无法确认时显示真实未知，不伪造完成或恢复 |
| R13 | P1 | 简单每日/每周安排；明确时区、下一次触发、暂停/恢复、错过策略与执行记录 |
| R14 | P1 | 用户可查看、添加、修改和删除长期偏好，并看到来源；记忆不会扩大执行权限 |
| R15 | P1 | 电脑、企业 Edge、设备和专家 Agent 按需接入；清晰区分连通与能力就绪 |
| R16 | P1 | 事件触发只提供明确来源与条件；去重、合并与授权由运行时实现，不做复杂编排器 |
| R17 | P0 | 中文自然、键盘可用、窄屏可完成主要流程；产品文档中英一致 |

R13–R16 的设计也在本文档组内完成；当前原型对安排和记忆提供操作，对真实连接、事件入口与设备执行保留明确的接入边界。

## 首版与后续

**首版产品闭环：** 默认 Agent、一个云端执行环境、对话与上下文、活动、成果、可靠停止/恢复、历史和最小工具连接。运行时坚持单活调度、Session 串行、持久化 Run/Task/Attempt 与结果确认。

**随后交付：** 简单持续安排、显式记忆管理、一个桌面或 Edge 适配器、专家 Agent 委托。设备能力与事件规则按真实用户目标接入，不让所有渠道成为首版上线门槛。

**条件扩展：** 多 Agent 管理台、复杂工作流、技能市场、团队角色、任意状态迁移、多活自动接管、离线授权和严格共享费用账本。它们各自需要业务场景和成本收益证明。首版不提供面向所有用户的模型参数面板或权限策略编辑器。

登录、模型凭据配置、文件存储与真正的运行时仍是生产实施工作。原型不接入身份服务，也不收集凭据；这并不意味着生产产品无需身份与数据隔离。

## 可度量目标

以下是待验证的产品目标，不是已测数据：首次用户在不求助的情况下完成一次交付；典型用户能在 30 秒内发出首个有效目标；至少 4/5 的形成性测试用户能找到成果并完成一次修改；所有停止与失败测试中都不出现假成功或未知动作重复提交。

记录首个有效目标、需要补充信息、连接阻塞、成果打开/编辑/下载、继续修改、停止请求/确认和恢复结果。分析使用匿名事件和对象引用，默认不记录消息正文、文件内容或私有推理。只有需要时再建设分析平台。

## 完成定义

需求、交互、领域状态与验收逐项对应；原型覆盖主要流程；明确展示模拟范围；视觉与响应式检查通过。生产产品另需真实模型、存储、适配器、身份、结果核对与故障验收，不能以原型截图替代。
